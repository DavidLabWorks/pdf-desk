# 桌面应用组件设计规范

先判断用户在当前界面要完成的任务，再选择目标项目已有的组件。字号、间距、圆角、颜色和控件尺寸取自目标项目的设计资源；缺少约定时，优先采用平台原生控件及其默认行为。可复用的是相同操作的含义、反馈和视觉层级，具体布局随内容密度、窗口空间和输入方式调整。

## 视觉层级

- **主内容与工具**。把主要空间留给用户正在处理的内容。常用操作靠近作用对象，相关操作成组；低频操作可收进菜单。悬浮控件需避开关键内容。
- **文字与表面**。用标题说明当前对象，用正文承载任务信息，用次要文字补充时间、来源或说明。同级信息使用同一文字角色。先用对齐与间距分组，有明确边界或遮叠关系时再加底板、边框或阴影。
- **颜色与尺寸**。按主操作、选中、次要、危险等语义选择主题资源。图标大小和可点击范围分别确定；紧凑布局仍要便于命中。检查目标平台支持的主题、对比度和显示缩放。

## 基础组件选型

| 用户意图 | 选择规则 |
|---|---|
| 执行一次动作 | 用命令按钮，以动词命名。多个动作并列时，只突出当前任务的主要动作。纯图标按钮提供可访问名称，含义不明显时加文字。 |
| 切换持续状态 | 即时生效的设置可用开关，工具模式可用切换按钮。控件呈现实际状态，切换后有可辨认的反馈。 |
| 从多个选项中选择 | 互斥且值得并排比较的选项用单选或分段控件；较长的集合用选择器或列表。多个独立选择用复选框。 |
| 输入或调整数值 | 精确值用数值输入，连续试调用滑块。输入字段提供标签、单位及必要约束；校验失败时保留输入，在字段附近说明如何修正。 |
| 浏览、选中或批量处理对象 | 让当前项、键盘焦点与批量选区分别可辨。操作应显示其作用范围，命令可用性随选择和权限更新。 |

## 弹窗与反馈

- **何时打断**。需要用户先作决定才能继续时用模态弹窗；临时调整参数可用就地面板，告知操作结果可用非模态通知。
- **如何组织**。标题点明任务或对象，正文只补充决定所需的信息。长列表或详情可滚动，关键操作保持可达。按钮用「保存副本」「移至回收站」这类能预告结果的名称。
- **默认动作与焦点**。输入类弹窗优先聚焦待编辑字段。可安全提交的任务可将有效提交设为默认；涉及删除或丢失修改时，默认动作优先保留数据。取消和关闭沿平台约定处理，只有明确提交才写入变更。
- **危险语义**。危险提示与实际后果相称，颜色、图标和动词共同说明动作。可逆偏好切换使用普通反馈。具体配色与按钮顺序遵循项目和平台约定。
- **过程与结果**。空集合、查询无结果、正在加载和加载失败应有各自的反馈。耗时任务呈现阶段，有可度量进度时显示进度；接受取消后先反馈「正在取消」，收到最终结果再结束任务状态。

## 复用时检查什么

针对实际组件走一遍主要操作、取消和失败路径。用键盘检查焦点流向，尤其是弹层关闭后焦点落在哪里。按需检查悬停、按下、选中、禁用、长文本和窄窗口。优先复用目标项目中同角色组件的样式和事件处理，再决定是否需要增加公共变体。
