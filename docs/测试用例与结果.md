# PDF Desk Windows 测试用例与结果

## 执行条件

桌面测试使用独立的 `PDFDESK_STATE_DIR`、自带测试 PDF 和临时输出，不操作日常书架。引擎用例位于 `windows/tests/PDFDesk.Tests`，样本来自 `tests/corpus` 和 `test_files`。桌面流程应核对用户可见状态；引擎断言只能证明对应的底层行为。

## 本轮实测

测试机为 Windows ARM64，系统内部版本 26300。应用按 win-arm64 构建，桌面测试通过 Windows UI Automation 操作真实窗口，并读取同一测试进程的计数器。每轮新建临时配置，编辑和打印都使用测试文档。

|用例|结果|核对依据|
|---|---|---|
|E01–E05|通过|Release 测试程序集的 463 项全部通过，失败 0、跳过 0。在 ARM64 测试宿主再次运行同一程序集，结果相同。|
|U01、U04|通过|切换到收藏和列表视图，核对 JSON 并重启检查收藏选中。切换深色及简体中文后核对两个设置值，重启后界面读到“收藏”。|
|U02|修复后通过|第二次打开 hello.pdf 的标签数不变。同时传入 slides.pdf 和 linked.pdf，两者均出现在标签栏，后者成为活动文档。|
|U03|通过|打开 book-1000.pdf，下一页使页码增大，放大后百分比变化，切换侧栏使开关状态改变。回主页退出时 ActiveIndex 为 -1，重启仍在主页并保留文档标签。|
|U05|通过|分别从最小化和隐藏到托盘启动另一个打开文件请求，检查原窗口可见且标题为请求的文档。|

|X02|部分验证|从文档菜单进入系统打印预览，验证 Microsoft Print to PDF 可选且存在页面缩放控件。尝试提交任务后系统打开了保存窗口，但未取得可核验的输出 PDF，输出页数和缩放效果尚未通过验收。实物打印和 Surface Pen 尾擦未做硬件实测。|

### 内存与句柄

M01 使用千页样本和多个常驻标签，再连续 48 次打开并关闭同一个约 9.4 MiB 的 PDF。通过标签的关闭按钮操作，每次核对标签数确实下降。下表来自最终 ARM64 Release 的同一进程。单位为 MiB，专用字节和工作集使用 Windows 进程计数器。

|采样点|专用字节|工作集|句柄|
|---|---:|---:|---:|
|空书架|84.9|179.1|948|
|打开千页文档及其他标签|502.6|613.1|1136|
|开关 1 轮|561.6|677.6|1144|
|开关 12 轮|523.3|642.1|1199|
|开关 24 轮|447.2|566.6|1208|
|开关 48 轮|514.0|633.9|1300|
|随后空闲 3 秒|469.9|590.0|1296|

同样 48 轮的修复中间版本在空闲 3 秒后仍占用 714.5 MiB 专用字节、1672 个句柄。最终版空闲专用字节低于打开千页文档后的基准，句柄较该基准多 160 个。另开独立进程，保留一个活动标签并开关 8 次文档：修复前堆中有 9 个 DocumentView；最终版连续 4 次采集均只剩 1 个，第四次也只剩 1 个 PdfViewer。48 轮未崩溃，句柄仍有净增长，长时间运行的句柄稳定性待验证。

另做冷启动对照，在主页恢复 0 个和 24 个从未激活的标签。修复前分别为 42 和 66 个线程。延迟创建渲染线程后分别为 41 和 41 个，专用字节分别为 83.2 和 104.0 MiB。这个对照只验证后台标签的线程开销。

### 复测步骤

在仓库根目录运行以下命令。ARM64 测试宿主和应用需安装项目指定版本的 .NET 及 Windows SDK。

```powershell
dotnet test windows/tests/PDFDesk.Tests/PDFDesk.Tests.csproj -c Release
dotnet vstest windows/tests/PDFDesk.Tests/bin/Release/net10.0/PDFDesk.Tests.dll /Platform:ARM64
dotnet build windows/src/PDFDesk.App/PDFDesk.App.csproj -p:Platform=ARM64 -r win-arm64 -c Release
```

桌面复测从空的临时目录开始，将该进程的 PDFDESK_STATE_DIR 指向该目录。按 U01–U06 与 X01 顺序执行。做 M01 时保持窗口大小、其他标签和缩放一致，在第 1、4、8、12、24、36、48 轮读取 PrivateMemorySize64、WorkingSet64、HandleCount。堆快照另起进程采集，以免采集产生的 GC 干扰正常读数。

## 修复清单

1. 文件启动参数原先只处理第一个路径。现在按传入顺序收集所有有效路径，重复路径仍激活现有标签。
2. 连续切换标签时，共用工具栏可能尚未进入可视树，但仍属于上一个阅读布局。现在先从实际拥有它的布局移除，再挂入新标签。
3. PDF 打开失败时，底层英文错误会直接进入中文界面。已补齐错误映射，损坏样本已验证中文反馈。
4. 恢复后台文档时，每个标签都会提前创建渲染线程。现在在有渲染任务或后台 PDF 操作时才创建线程。
5. 永久关闭标签时释放 Win2D 画布，停止调度器与计时器，解除输入、列表和阅读事件绑定，拆除模板与内容引用。普通标签切换继续保留阅读状态。

## 深色模式界面复测（2026-11-20）

Windows ARM64，应用版本 0.0.1。使用独立的用户配置和三个示例 PDF。先操作发行版窗口观察原样式，再在同一份源码的测试构建里打开实际 WinUI 控件、采集渲染图并读取活动主题。主题切换顺序包含深色 → 浅色 → 跟随系统（本机为浅色）→ 深色。

| 区域 | 已验证的状态 | 结果 |
| --- | --- | --- |
| 书架和设置 | 最近卡片、列表、悬浮、收藏与空收藏、空书架、右键菜单、默认应用状态 | 深色卡片悬浮时提亮；标题、文件名、路径、次要说明和选中状态可辨。 |
| 阅读器 | 缩略图、目录、书签、夜间阅读、演示、搜索、命令面板、文档和缩放菜单 | 阅读区随界面切换；PDF 反色由夜间阅读控制。 |
| 工具浮层 | 画笔、荧光笔、橡皮擦、签名列表、便签内容、文字格式栏、页面布局 | 查看了各浮层的实际内容。文字格式选中背景在深色、浅色、再切回深色时分别为 `#4C4E52`、`#DBDBDB`、`#4C4E52`。 |
| 对话框 | 文档属性、快捷键、报告问题、新建 PDF、保存单个及多个文档、找回文件、重命名书签、编辑便签、创建签名、签名详情、外部链接、表单文字样式、合并批注 | 各对话框实际使用深色主题。取消操作后可继续打开其他对话框。签名画布保留白纸预览。 |
| 桌面集成 | 默认应用提醒和托盘菜单 | 在隔离配置中检查了提醒的内容与按钮、托盘菜单的主题和文字。提醒通过测试条件触发。 |
| 通知 | 窗口级无标题提示，以及阅读器内的信息、成功、警告、错误四种提示 | 使用同一通知组件注入样本。四种提示均已渲染，5 秒计时结束后均收起。无标题提示只有一行内容区。 |

这轮覆盖 PDF Desk 自绘界面和 WinUI 控件。Windows 文件选择器与打印窗口由系统提供，未逐项验证系统主题、打印机驱动、高对比度和自定义强调色组合。
